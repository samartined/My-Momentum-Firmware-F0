# Multi-agent system ADRs

This directory contains the **Architecture Decision Records (ADRs)** generated by the Tripartite Council (L3) or by escalation to the user (L4) during system operation.

## Important distinction

- `.claude/design/system-design.md` documents **the agent system** (how it works). Its D1-D27 decisions are about the architecture of the system itself.
- The **ADRs in this directory** document **operational decisions taken BY the system** about the firmware or about its own evolution during normal operation (Phase 2 onward).

If the decision is "how the agent system works", it goes in `system-design.md`. If the decision is "what do we do about this specific feature/refactor/agent", it goes here as an ADR.

## Naming and numbering

- Each ADR: `ADR-NNNN-<slug>.md`
- `NNNN`: monotonic number (0001, 0002, ...) in creation order.
- `<slug>`: kebab-case of the title (e.g. `add-subghz-protocol-x`).

## Structure of an ADR

Each ADR has the following mandatory sections:

1. **Header**: title, status, date, decision-level (L3/L4), council-id (if L3), reference to the dossier in `pending/<id>/`.
2. **Status**: `proposed | accepted | superseded by ADR-NNNN | deprecated`.
3. **Context**: description of the problem or decision to be made, reconstructed from the dossier (not from conversational memory).
4. **Alternatives considered**: ≥2 real alternatives with explicit trade-offs.
5. **Decision**: the option chosen + why.
6. **Council votes** (L3 only): table with council member, angle, vote (`YES` / `NO` / `YES-WITH-CONDITIONS`), reasoning, and risks. A minority vote is explicitly documented as a known risk if the decision proceeded with 2-of-3.
7. **Consequences**: positive, negative/assumed risks, reversibility (does it match G3? how is it undone?).
8. **Follow-ups**: dependent derived tasks or decisions.

## The `pending/<id>/` directory

While the Council is in progress (before the ADR is closed), intermediate artifacts live in `.claude/decisions/pending/<UUIDv7>/`:

- `dossier.md`: built by the master before invoking the Council (schema defined in `system-design.md` → "Mandatory dossier before L3" section).
- `concejal-1.md`, `concejal-2.md`, `concejal-3.md`: parallel round-1 verdicts.
- `synthesis.md` (if applicable): the master's synthesis of the 3 verdicts for round 2.
- `vote-round-2.md`, `vote-round-3.md`: votes on the synthesis and cross-validation of conditions.

When the ADR is closed (`status: accepted` after 2-of-3 YES or unanimity), the artifacts in `pending/<id>/` may be archived or kept per retention policy. Deleting them matches G3 #9 (audit logs) — only via a human PR.
